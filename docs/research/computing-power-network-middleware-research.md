## 摘要

本报告围绕 KIAS 定位的三大核心能力——**异构调度**、**分布式Agent长周期运行**、**AIOps**——进行系统性调研。结合学术论文、开源项目、行业趋势和 KIAS 当前代码库，提出架构演进建议和开发任务清单。

**核心结论**：KIAS 已具备 60-70% 的基础能力，但需要在三个方向做深度增强：
1. 异构调度需要从"Agent 分层"升级到"全栈算力感知"
2. 长周期运行需要从"单节点恢复"升级到"分布式状态机"
3. AIOps 需要从"健康检查"升级到"预测式自愈"

## 一、异构调度：从 Agent 分层到算力网调度

### 1.1 行业现状

算力网时代，GPU 资源呈现三大特征：
- **异构性**：H200/H20/A100/昇腾/寒武纪混部
- **分布式**：跨数据中心、跨区域调度
- **多租户**：同一集群服务多个业务方

|------|-------|---------|-------------|

### 1.2 KIAS 当前状态评估

| 能力 | 模块 | 状态 | 差距分析 |
|------|------|------|---------|
| RR/LL/RA/CA 调度算法 | scheduler/algorithms | ✅ 有 | 缺 GPU 感知维度 |
| Agent 能力分层 | scheduler/agent_tier | ✅ 有 | 仅 3 级，需支持自定义维度 |
| 缓存感知路由 | scheduler/cache_aware | ✅ 有 | 仅本地缓存，缺跨节点缓存 |
| 反调度器 | scheduler/descheduler | ✅ 有 | 策略需扩展（负载均衡、亲和性反调度） |
| GPU 感知 | scheduler/gpu_aware | ✅ 有 | 基础版，缺 MIG/时间切片支持 |
| 模型路由 | model-router | ✅ 有 | 需增加算力成本维度 |
| 边缘调度 | scheduler/edge | ✅ 有 | 基础版，需增强 |

**差距汇总**：
1. **GPU 资源抽象层缺失** — 没有统一的 GPU 资源模型（MIG、vGPU、时间切片）
2. **跨域调度缺失** — 仅支持单集群调度，不支持跨数据中心
3. **资源画像缺失** — 没有历史负载分析和预测
4. **Gang Scheduling 缺失** — 多 Agent 协同任务无法保证原子调度

## 二、分布式Agent长周期运行

### 2.1 行业现状

Long-running Agents 的核心挑战：
- **状态持久化**：Agent 运行数天/数周，状态不能丢
- **故障恢复**：节点故障后 Agent 必须能在其他节点恢复
- **跨节点通信**：Agent 的工具调用可能在不同节点
- **资源隔离**：多 Agent 共享集群，互不干扰
- **检查点**：长任务需要中间状态保存，支持回滚

#### 关键项目对比

| 项目 | 核心能力 | 长周期运行支撑 | KIAS 可借鉴 |
|------|---------|--------------|-------------|

| [Prefect](https://github.com/PrefectHQ/prefect) | 数据流编排、检查点、恢复 | ✅ 强 | 检查点策略 |
| [Dagster](https://github.com/dagster-io/dagster) | 数据管道编排、资产导向 | ✅ 中 | 资产导向编排 |
| [Hermes Agent](reference-projects/hermes-agent) | Skill 系统、cron 任务 | ⚠️ 弱 | Skill 系统设计 |
| [rig](reference-projects/rig) | Rust Agent 框架、工具注册 | ⚠️ 弱 | Rust Agent 模式 |

### 2.2 KIAS 当前状态评估

| 能力 | 模块 | 状态 | 差距分析 |
|------|------|------|---------|
| 心跳监控 | controller/heartbeat | ✅ 有 | 仅单节点，缺分布式心跳 |
| 故障恢复 | controller/recovery | ✅ 有 | 仅重启，缺状态迁移 |
| 生命周期管理 | controller/lifecycle | ✅ 有 | 缺跨节点迁移 |
| 状态持久化 | data-store | ✅ 有 | SQLite 单节点，缺分布式存储 |
| 检查点 | workflow-engine/checkpoint | ✅ 有 | 基础版，缺增量检查点 |
| 运行时循环 | controller/runtime_loop | ✅ 有 | OODA 循环，缺分布式协调 |
| 三层记忆 | team-engine/memory | ✅ 有 | 缺跨 Agent 记忆共享 |
| 自主决策 | autonomy-controller | ✅ 有 | 缺分布式共识 |

**差距汇总**：
1. **分布式状态管理缺失** — SQLite 不支持分布式，需要 etcd/分布式 KV
2. **Agent 迁移缺失** — 节点故障后无法将 Agent 状态迁移到其他节点
3. **分布式检查点缺失** — 长任务的中间状态无法跨节点恢复
4. **跨 Agent 通信缺失** — Agent 间通信仅支持本地，缺跨节点 RPC
5. **分布式共识缺失** — 多 Agent 决策无法达成一致

**开发任务**：

2. **P1**: Agent 迁移器 — 节点故障时自动将 Agent 状态迁移到健康节点
3. **P2**: 分布式检查点 — 支持增量检查点 + 跨节点恢复
4. **P2**: Agent 间 RPC — 基于 gRPC 的跨节点 Agent 通信
5. **P3**: 分布式共识 — 基于 Raft 的多 Agent 决策协调

## 三、AIOps：从健康检查到预测式自愈

### 3.1 行业现状

AIOps（AI for IT Operations）是算力网时代的核心需求。随着集群规模增长，人工运维已不可行。

#### AIOps 能力层次

```
L4: 预测式自愈 — 在故障发生前预测并预防
L3: 根因分析 — 自动定位故障根因
L2: 异常检测 — 自动发现异常模式
L1: 健康检查 — 定期检查系统状态
L0: 日志收集 — 收集系统日志和指标
```

#### 关键项目对比

| 项目 | 核心能力 | AIOps 层级 | KIAS 可借鉴 |
|------|---------|-----------|-------------|
| [Prometheus + Grafana](https://prometheus.io) | 指标收集 + 可视化 | L0-L1 | 指标采集架构 |
| [PagerDuty](https://www.pagerduty.com) | 事件管理 + 告警 | L1 | 事件路由 |
| [BigPanda](https://www.bigpanda.io) | AI 驱动事件关联 | L2-L3 | 事件关联算法 |
| [Moogsoft](https://www.moogsoft.com) | AI 异常检测 + 根因分析 | L2-L3 | 异常检测算法 |
| [Datadog](https://www.datadoghq.com) | 全栈可观测性 | L0-L2 | 可观测性架构 |
| [Kubernetes](https://kubernetes.io) | 自愈（livenessProbe + restart） | L1 | 自愈模式 |
| [Chaos Mesh](https://chaos-mesh.org) | 混沌工程 | L1-L2 | 故障注入测试 |

#### 学术前沿

| 领域 | 关键论文/方法 | KIAS 启发 |
|------|-------------|----------|
| 异常检测 | Isolation Forest, LOF, Autoencoder | 多维度异常检测 |

| 能力 | 模块 | AIOps 层级 | 差距分析 |
|------|------|-----------|---------|
| 健康检查 | controller/health | L1 | 仅基础探针，缺多维度检查 |
| 心跳监控 | controller/heartbeat | L1 | 缺心跳质量分析 |
| 故障恢复 | controller/recovery | L1 | 指数退避重启，缺根因分析 |
| 监控面板 | monitor | L0 | 基础指标，缺告警规则 |
| 事件系统 | controller/events | L0 | 有事件总线，缺事件关联 |
| 遥测 | monitor | L0 | 基础 tracing，缺指标聚合 |

**差距汇总**：
1. **异常检测缺失** — 仅被动健康检查，无主动异常发现
2. **根因分析缺失** — 故障后仅重启，不分析根因
3. **预测性维护缺失** — 无资源需求预测、无容量规划
4. **自动修复策略单一** — 仅重启，缺降级、迁移、扩容等策略
5. **事件关联缺失** — 告警风暴、事件重复、关联分析

```

  ↓
监控 → Monitor → AIOps（异常检测 → 根因分析 → 自愈）
  ↓

```

## 七、总结

### KIAS 的差异化定位

KIAS 不是另一个 K8S，不是另一个 Temporal，不是另一个 Prometheus。

**KIAS = 算力网时代的 Agent 操作系统**

独特价值：
1. **唯一同时覆盖调度 + 运行时 + AIOps 的 Agent 平台**
2. **唯一支持 Agent 自进化的平台**（Skill 自提取 + 自循环开发）
3. **Rust 实现**，性能和安全性远超 Python/Node 方案
4. **开源 + 多模型**，不锁定任何供应商

### 下一步行动

1. 立即开始 AIOps 异常检测引擎（P1）
2. 同步推进 GPU 资源抽象层（P1）
3. 分布式状态存储抽象为后续分布式能力打基础（P1）

**不停。正向循环是 Long-running Agents 的核心。**
