# PrfaaS：选择性卸载调度架构分析

> 来源：微信公众号 2026-05-18（Moonshot AI 论文）
> 用途：KIAS 调度器设计参考

## 一、核心思想

**选择性卸载（Selective Offloading）**：只把值得的请求送到远端高算力集群。

不是所有请求都需要最强算力。短请求的 Prefill 是内存瓶颈（不是计算瓶颈），送到高算力集群反而浪费。

## 二、三子系统架构

| 子系统 | 组件 | KIAS 映射 |
|--------|------|-----------|
| 计算 | PrfaaS 集群（H200）+ 本地 PD 集群（H20） | Agent 能力分层（强/弱 Agent） |
| 网络 | RDMA（集群内）+ 以太网（集群间） | Agent 通信（本地快+远程慢） |
| 存储 | 混合前缀缓存池 | 共享记忆/知识库 |

## 三、双时间尺度调度

### 短期调度：带宽感知 + 缓存感知路由

- 设长度阈值 t
- 增量 Prefill > t → 发到高算力集群
- 增量 Prefill ≤ t → 留在本地处理
- 实时监控带宽利用率和队列深度

**KIAS 映射**：
- 任务复杂度阈值
- 简单任务 → 本地弱 Agent
- 复杂任务 → 远程强 Agent
- 实时监控 Agent 负载

### 长期调度：流量驱动的资源再分配

- Prefill/Decode 实例比例动态调整
- 流量模式变化时重新计算最优配置

**KIAS 映射**：
- Agent 池大小动态调整
- 根据任务模式调整 Agent 比例

## 四、关键数据

| 指标 | PrfaaS-PD | 同构 PD | 朴素异构 PD |
|------|-----------|---------|-------------|
| 吞吐量提升 | **+54%** | 基准 | +16% |
| P90 TTFT | 基准 | 高 64% | - |
| 跨集群带宽 | 13 Gbps | 不适用 | 更高 |

**核心洞察**：光有异构硬件不够，得有聪明的调度。选择性卸载 + 带宽感知 + 缓存感知 = 54% 提升。

## 五、对 KIAS 的启发

1. **Agent 能力分层**：不是所有任务都需要最强 LLM
2. **任务复杂度评估**：自动判断任务应该路由到哪类 Agent
3. **成本优化**：简单任务用便宜 Agent，复杂任务用强 Agent
4. **缓存复用**：相似任务共享上下文（前缀缓存）
5. **动态扩缩容**：根据任务模式调整 Agent 池
