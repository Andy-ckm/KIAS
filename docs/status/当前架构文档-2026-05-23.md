## 一、项目概述

### 1.1 基本信息

| 属性 | 值 |
|------|-----|
| 项目名 | AgentGuard（原 KIAS） |
| 语言 | Rust 1.95 |
| 架构 | 36 crate monorepo |
| 总代码量 | 143K+ LOC |
| 测试数 | 5241+ |
| 分支策略 | 仅 main |
| License | MIT |

**定位**：让AI Agent可追溯、透明、可控。企业级AI Agent治理与合规系统，面向医疗/制药/器械行业（GxP合规）。

### 1.2 技术栈

**运行时**：
- Tokio（异步运行时，`full` features）
- async-trait

**序列化**：
- serde + serde_json + serde_yaml + toml

**错误处理**：
- thiserror + anyhow

**可观测性**：
- tracing + tracing-subscriber
- Prometheus metrics

**核心依赖**：
- chrono（时间）
- uuid（ID生成）
- sha2/blake3（哈希）
- bytes（字节处理）
- config（配置管理）
- once_cell（单例）

## 四、架构分层（设计文档 vs 实际）

### 4.1 设计分层（docs/architecture.md）

```
L3: Handlers     (API路由、请求处理)
L2: Services     (业务逻辑、调度算法)
L1: Models       (数据模型、配置结构)
L0: Common       (工具函数、错误类型)
```

**依赖规则**：L3→L2,L1,L0 | L2→L1,L0 | L1→L0
**禁止反向依赖**

### 4.2 实际架构（基于代码分析）

```
HTTP/gRPC请求
    ↓
api-server (axum + tonic)
    ↓
┌──────────────────────────────────────┐
│         Controller (Agent Pod)       │
│   ┌──────────┐    ┌──────────────┐   │
│   │Scheduler │    │AutonomyCtlr  │   │
│   └────┬─────┘    └──────┬───────┘   │
│        ↓                    ↓          │
│   ┌────┴────────────────────┴─────┐   │
│   │      Agent Runtime             │   │
│   └────┬────────────────────┬─────┘   │
│        ↓                    ↓          │
│  ┌─────┴─────┐      ┌──────┴──────┐  │
│  │goal-engine │      │ auto-loop    │  │
│  └─────┬─────┘      └──────┬──────┘  │

    ↓
┌───────────────┐
```

## 八、API Server 路由设计

**技术**：axum (HTTP) + tonic (gRPC)

**HTTP 端点**：
```
/health                    GET   健康检查
/api/v1/agents             GET   Agent列表
/api/v1/agents             POST  创建Agent
/api/v1/agents/:id         GET   Agent详情
/api/v1/agents/:id         DELETE
/api/v1/tasks              POST  提交任务
/api/v1/tasks/:id          GET   任务状态
/api/v1/tasks/:id/stream   GET   SSE实时推送
/api/v1/tasks/:id/cancel   POST  取消任务
```

**A2A Protocol**：
```
/.well-known/agent.json    GET   Agent Card发现
/a2a/v1/agents             GET   所有Agent Card
/a2a/v1/tasks              POST  发送任务
```

**路由策略**：Direct / Capability / LoadBalanced / Broadcast / Chain
