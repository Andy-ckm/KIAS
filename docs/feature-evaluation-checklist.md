# KIAS 功能评估流程

> 钱学森原则：整体性——每个功能必须评估对整体的影响

## 评估清单（新功能/PR 必须通过）

### 1. 必要性评估
- [ ] 这个功能解决什么具体问题？
- [ ] 现有功能能否覆盖？（搜索 codebase）
- [ ] 不做会怎样？（影响程度）

### 2. 重复性评估
- [ ] 是否与现有模块功能重叠？
- [ ] 能否扩展现有模块而非新建？
- [ ] 是否有现成的开源方案？（下载分析）

### 3. 工程化评估
- [ ] 有论文或源码参考吗？
- [ ] 测试覆盖了吗？（不是 assert(true)）
- [ ] 文档同步了吗？

### 4. 整体影响评估
- [ ] 对编译时间的影响？
- [ ] 对二进制大小的影响？
- [ ] 对架构分层的影响？（L0→L1→L2→L3）
- [ ] 对其他 crate 的影响？

### 5. 质量门禁
- [ ] `cargo fmt --check`
- [ ] `cargo clippy -- -D warnings`
- [ ] `cargo test` 全通过
- [ ] 无 non-test unwrap

## 违反处理

违反评估流程 = 返工。不接受"先堆上去再说"。
