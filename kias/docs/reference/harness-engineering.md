# Harness Engineering（工程治理层）

> 来源：用户分享的技术文档，2026-05-21
> 用途：AgentGuard 定位和架构参考

## 核心定义

Harness 不替代执行工具，它定义执行工具必须遵守的**工程上下文和协作协议**，是一种结构化的、可被代理自动检索和执行的、承载了人类工程智慧的"规范体系"。

## L5 定义：Harness Engineering

将 Harness 的设计、构建与演进本身视为一门独立的高阶工程学科。它要求工程师站在工程治理的高度，设计一套可沉淀、可复用、可维护的规范体系。

## 工程制品清单

| 制品 | 功能 | 分类 |
|------|------|------|
| AGENTS.md | 全局规范与默认行为 | 默认规则 |
| skills/ | 按需加载的原子能力 | 规范 |
| agents/ | 专职角色与内部指令 | 规范 |
| .playground/commands/ | 共享的工程行动 | 行动 |
| .context/ | 事实/决策/领域的知识库 | 上下文 |
| service-matrix.md | 边界、owner、依赖图 | 上下文 |
| requirements/ | 结构化意图 (PRD) | 意图 |
| scripts/ | 可复用的确定性逻辑 | 行动 |

## 完整需求链路（示例）

1. 人类在 `requirements/` 创建 PRD（意图）
2. 系统自动注入 AGENTS.md 全局规范（默认规则）
3. 首席工程师创建并执行计划（决策）
4. 工程师写作代码（产出）
5. 立即执行 CI 脚本 `scripts/ci.sh`（行动）
6. 专家角色（QA 审计员）被激活（角色）
7. 专家从 `.context/` 拉取历史审计报告（知识）
8. 专家触发 `.playground/commands/audit.run-full`（行动）
9. 审计专家生成报告并由工程师提交（产出）

## L4 → L5 的关键跃迁

| 维度 | L4 工程代理 | L5 工程治理 |
|------|------------|------------|
| 核心能力 | 高效完成代码任务 | 设计和维护 Harness |
| 核心资产 | 任务完成记录 | 可复用的工程制品 |
| 组织依赖 | 个人经验 | 组织记忆与体系 |
| Agent 交互模式 | 被动指令执行 | 主动检索、角色分配、策略驱动 |
| 价值体现 | 任务级效率 | 系统级效率与治理 |

## 对 AgentGuard 的启示

1. **AgentGuard 本身可以是一个 Harness**：定义 AI Agent 必须遵守的合规上下文和协作协议
2. **工程制品体系**：AgentGuard 的配置、规则、审计报告就是工程制品
3. **可复用性**：GxP 合规规则应该像 skills/ 一样可按需加载
4. **组织记忆**：AgentGuard 的审计日志就是组织记忆
5. **L5 定位**：AgentGuard 不是 IDE，不是 CI，而是 AI Agent 的工程治理层
