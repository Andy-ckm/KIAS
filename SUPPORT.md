# Support

## Community support

Use GitHub issues for reproducible bugs and GitHub discussions for design questions, usage help, and ideas. Search existing threads before posting.

A useful support request includes:

- KIAS version or commit;
- operating system and Rust version;
- minimal configuration with all secrets removed;
- exact command and observed error;
- a minimal reproduction using synthetic data;
- relevant logs after redacting tokens, identities, query strings, message content, paths, and private infrastructure details.

## Security and privacy

Do not post vulnerabilities, credentials, personal data, customer information, internal company names, tenant identifiers, proprietary documents, or production logs in public issues. Follow `SECURITY.md` for private reporting.

## Scope

Community support is best effort. Maintainers prioritize security, correctness, reproducible defects, documentation gaps, and changes that benefit a broad set of users.

Deployment-specific consulting, private integrations, and organization-specific compliance mappings are outside the public project's support commitment.
