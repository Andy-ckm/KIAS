## 测试自动化

### 测试命令
```bash
# 运行所有测试
cargo test --workspace -- --nocapture 2>&1 | tail -5

# 运行特定模块测试
cargo test --package model-router -- --nocapture

# 运行特定测试用例
cargo test --package model-router key_rotation -- --nocapture

# 生成测试覆盖率报告
cargo tarpaulin --workspace --out Html
```

### 测试报告
- **位置**：`docs/test-report.md`
- **格式**：Markdown + HTML
- **更新频率**：每次Sprint结束

## 测试策略

### 测试金字塔
```
    端到端测试（少量）
   /          \
  集成测试（中量）
 /              \
单元测试（大量）
```

### 测试原则
1. **每个公共函数**至少一个测试用例
2. **边界条件**必须测试（空值、最大值、负值）
3. **错误路径**必须测试（网络错误、文件错误、权限错误）
4. **并发场景**必须测试（死锁、竞态条件）
5. **性能敏感**代码必须基准测试

### 测试数据管理
- **测试数据**：使用内存文件系统（MemoryFs）
- **测试配置**：独立测试配置文件
- **测试清理**：每个测试后自动清理资源
- **测试隔离**：测试间无共享状态

## 测试维护指南

### 新增测试要求
1. 每个新特性必须包含测试用例
2. 测试必须覆盖正常路径和错误路径
3. 测试必须可重复执行（无副作用）
4. 测试必须有清晰的断言和错误信息

### 测试修复流程
1. 失败测试必须在24小时内修复
2. 修复后必须运行完整测试套件
3. 修复必须记录在变更日志中
4. 定期清理过期测试用例

### 测试监控
- **每日构建**：自动运行所有测试
- **覆盖率监控**：每周检查覆盖率变化
- **性能监控**：检测测试执行时间趋势
- **质量门禁**：覆盖率低于80%时阻止合并
