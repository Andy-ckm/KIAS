# AgentGuard 变更影响分析

> 追踪每次变更的影响范围，确保变更可控可追溯

## 变更分类

### 1. 架构变更
**影响范围**：整个系统架构
**风险等级**：高
**审查要求**：架构委员会审查

**示例**：
- 新增核心模块
- 修改通信协议
- 变更数据存储方案

### 2. 接口变更
**影响范围**：模块间交互
**风险等级**：中
**审查要求**：接口设计审查

**示例**：
- 修改API接口
- 变更数据格式
- 调整配置参数

### 3. 实现变更
**影响范围**：单个模块
**风险等级**：低
**审查要求**：代码审查

**示例**：
- 优化算法
- 修复Bug
- 重构代码

### 4. 文档变更
**影响范围**：文档系统
**风险等级**：低
**审查要求**：文档审查

**示例**：
- 更新用户手册
- 修改API文档
- 补充架构文档

## 变更影响矩阵

### 模块依赖关系
```
common ←── model-router ←── controller ←── api-server
   ↑           ↑               ↑
   │           │               │
   └─── team-engine ←── scheduler
           ↑
           │
      mcp-protocol
```

### 影响传播规则
1. **common变更**：影响所有上层模块
2. **model-router变更**：影响controller和api-server
3. **controller变更**：影响api-server
4. **team-engine变更**：影响scheduler
5. **mcp-protocol变更**：影响team-engine
6. **scheduler变更**：影响api-server

## 变更影响分析流程

### 1. 变更识别
```bash
# 查看变更文件
git diff --name-only HEAD~1

# 查看变更类型
git diff --stat HEAD~1

# 查看变更内容
git diff HEAD~1
```

### 2. 影响分析
```bash
# 查找依赖该模块的代码
grep -r "model_router" crates/ --include="*.rs"

# 查找使用该函数的代码
grep -r "fn xxx" crates/ --include="*.rs"

# 查找导入该模块的代码
grep -r "use model_router" crates/ --include="*.rs"
```

### 3. 风险评估
1. **直接依赖**：直接使用变更模块的代码
2. **间接依赖**：通过其他模块间接使用
3. **配置依赖**：通过配置文件使用
4. **测试依赖**：测试代码中的使用

### 4. 测试验证
```bash
# 运行受影响模块的测试
cargo test --package model-router

# 运行依赖模块的测试
cargo test --package controller

# 运行完整测试套件
cargo test --workspace
```
